# sshkeeper v0.7.2 — Windows launch, tunnels, and portable synced keys

v0.7.2 completes the Windows work that was not included in v0.7.1 and fixes
cross-platform key paths discovered while pairing a Linux/Windows dual-boot
machine.

## Fixed

- **Launch from Windows Explorer.** sshkeeper no longer refuses a normal
  double-click launch through Cobra's mousetrap guard. Fatal startup errors
  remain visible instead of the console window disappearing immediately.
- **Windows password and key-passphrase authentication.** The Windows build now
  drives the system OpenSSH client through ConPTY, including stored password
  and key-passphrase prompts.
- **Background tunnels on Windows.** Background ssh.exe -N processes are
  detached from sshkeeper's console/process group and their liveness is checked
  through the Windows process API instead of Unix Signal(0) semantics.
- **Portable synchronized SSH-key paths.** A profile synchronized from Linux no
  longer keeps /home/.../.ssh/... on Windows (and vice versa). Keys below
  .ssh are represented as ~/.ssh/... inside the encrypted bundle and
  materialized below the receiving user's local home. Profiles store the local
  absolute path after import.
- **Legacy bundle compatibility.** Existing v0.7.0/v0.7.1 key records containing
  absolute Linux or Windows paths are translated during the next sync; no
  manual re-pairing or database migration is required.

## Validation

CI now runs native Windows tests for ConPTY, background-process creation, and
cross-platform synchronized key paths, in addition to the existing Linux/macOS
tests and release-target cross-builds.
