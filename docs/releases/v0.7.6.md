# sshkeeper v0.7.6 — repair local key paths on a quiet sync

v0.7.6 fixes the remaining upgrade case where the shared sync bundle is
already correct but a local Windows profile still points at a Linux identity
path.

## Fixed

- **Local repair no longer depends on Incoming records.** Before merge, sync
  now checks already-synchronized profiles against the remote key records and
  repairs device-local key paths independently from whether anything changed
  in the shared bundle.
- **Quiet sync repairs Windows state.** A profile left with
  `/home/user/.ssh/id_rsa` is rewritten to the receiving device's local
  `.ssh` path and the synchronized private/public key is materialized there.
- **Shared storage stays untouched when it is already correct.** The
  regression test verifies that `sshkeeper.sync` remains byte-for-byte
  unchanged during this local-only repair.
- **Safety remains strict.** Repair only applies to a profile already linked
  to its remote server record and never overwrites a different existing local
  private key.

No re-pairing or manual edit is required. Upgrade and run synchronization once.
