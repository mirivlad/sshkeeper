# sshkeeper v0.8.2 — event-driven Session Workspace

v0.8.2 fixes excessive CPU usage introduced by the embedded Session Workspace
in v0.8.0.

## Fixed

- **Removed the 50 ms workspace polling loop.** SSH tabs no longer force a full
  Bubble Tea redraw twenty times per second while idle.
- **No duplicate refresh chains.** Opening additional tabs or typing in a
  session no longer creates additional independent timer loops.
- **PTY/ConPTY output drives redraws.** Each session now notifies the TUI only
  when terminal output actually arrives or the SSH process exits. Output bursts
  are coalesced naturally by rendering the emulator's latest state.
- **Idle tabs stay idle.** Regression tests verify that one and three idle SSH
  workspace sessions produce no synthetic refresh events.
- **Quick help includes workspace controls.** The `?` help screen now documents
  `Alt+Left/Right`, `Alt+0`, `Alt+1…9`, and `Alt+W`.

The existing 10-second runtime status refresh for tunnel/tmux indicators
remains; it is unrelated to terminal rendering and is intentionally low
frequency.
