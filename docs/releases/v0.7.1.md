# sshkeeper v0.7.1 — delayed pairing for dual-boot and offline devices

v0.7.1 adds a pairing path for devices that cannot be online at the same time,
most notably two operating systems on one dual-boot PC.

## Added

- **24-hour offline pairing.** In Settings → Synchronization choose
  **Add later (24h)**, or run **sshkeeper sync add-device --offline**.
  sshkeeper creates a one-time **SKP1-...** code with 128 random bits of
  entropy. Save the code; if a separate app syncs the storage folder, let it
  finish uploading first. Then shut down or reboot and enter the code on the
  other device later.
- **No old-device master password for offline pairing.** The long random code
  carries enough entropy on its own, so the other OS/device only needs the
  SKP1 code and access to the same sync storage.
- **Clear secret formats.** Six digits mean normal 10-minute pairing,
  SKP1 means 24-hour offline pairing, and the existing Base32 recovery key
  remains the emergency recovery path.

## Security

The existing six-digit flow is unchanged: it is valid for ten minutes and is
combined with the old device's master password through Argon2id.

The new offline code is not a longer-lived six-digit PIN. It contains 128 bits
of cryptographically random data, is one-time, expires after 24 hours, and the
pending pairing blob is deleted after a successful join. Git sync continues to
store pairing only on its temporary pairing branch, never in the sync branch
history.

## Compatibility

No data migration is required. Existing sync spaces, vaults, profiles,
passwords, and synchronized SSH keys remain compatible with v0.7.0.
